Définition

C'est quoi SQLDelight ?

SQLDelight est un générateur de code créé par Cash App (Square). Tu écris tes requêtes SQL dans des fichiers .sq, et SQLDelight génère automatiquement du code Kotlin entièrement typé.

Fini les strings SQL hardcodées qui crashent en prod. Fini les Cursor.getString(0) à la main. SQLDelight lit ton schéma et crée des fonctions Kotlin qui retournent directement tes data classes.

Le gros avantage : c'est du Kotlin Multiplatform (KMP). Le même code SQL tourne sur Android, iOS, Desktop et le Web.

Android iOS (Native) JVM/Desktop JavaScript WASM
User.sq 
-- Tu écris du SQL normal
CREATE TABLE User (
  id        INTEGER NOT NULL PRIMARY KEY,
  username  TEXT NOT NULL,
  email     TEXT NOT NULL
);

selectAll:
SELECT * FROM User;
↓ SQLDelight génère automatiquement
UserQueries.kt (généré) 
// Ce code est généré — tu ne le touches pas
fun selectAll(): Query<User> { ... }

// Utilisation dans ton code
val users = db.userQueries
  .selectAll()
  .executeAsList()
// users: List<User> ✅ Typé !

💡 Comparaison avec Room (Android)

Room et SQLDelight font des choses similaires, mais SQLDelight fonctionne sur toutes les plateformes Kotlin (KMP), pas seulement Android. Room reste plus simple pour un projet purement Android. SQLDelight brille dès que tu veux partager ta couche données entre Android et iOS.

Comprendre

Les concepts clés

Avant de coder, comprends ces 4 piliers. Tout le reste en découle.

🗂️

Fichiers .sq

Tu écris ton schéma SQL (CREATE TABLE) et tes requêtes nommées dans des fichiers .sq. Un fichier par table, rangé dans src/commonMain/sqldelight/. SQLDelight lit ces fichiers et génère le code Kotlin correspondant à chaque build.

⚡

Requêtes nommées

Chaque requête SQL dans ton fichier .sq a un nom : selectAll: ou insertUser:. SQLDelight génère une fonction Kotlin avec ce même nom dans une classe UserQueries. C'est le cœur du système.

🔒

Type safety à la compilation

Si tu écris SELECT * FROM Ussser (faute de frappe), SQLDelight te crie dessus au moment du build — pas au runtime. Plus de NullPointerException sur ta base de données en production.

🔄

Drivers interchangeables

SQLDelight utilise un driver qui est la couche native. Android = AndroidSqliteDriver, iOS = NativeSqliteDriver, Tests = JdbcSqliteDriver. Ton code SQL commun ne change pas.

📡

Reactive avec Flow

Les requêtes retournent des Query<T> que tu peux convertir en Flow<List<T>> via les extensions asFlow().mapToList(). Ta UI se met à jour automatiquement quand la base change.

🛠️

Migrations .sqm

Pour modifier ton schéma entre versions, crée des fichiers 1.sqm, 2.sqm… SQLDelight applique les migrations dans l'ordre. Tu peux aussi tester automatiquement que tes migrations sont cohérentes.

Installation

Mise en place pas à pas

Pour un projet Android pur ou KMP. Chaque étape est expliquée.

1

Ajouter le plugin SQLDelight

Dans ton build.gradle.kts de niveau projet. Ce plugin ajoute la tâche de génération de code.

build.gradle.kts (projet) 
plugins {
  // Dans le bloc plugins root
  id("app.cash.sqldelight") version "2.0.2" apply false
}
i

Le apply false signifie que le plugin est déclaré mais pas encore appliqué ici — il sera appliqué dans le module qui en a besoin (app/ ou shared/).

2

Configurer le module app

Dans ton build.gradle.kts du module app (ou shared pour KMP).

app/build.gradle.kts 
plugins {
  id("app.cash.sqldelight") // ① Appliquer le plugin
}

sqldelight {
  databases {
    create("AppDatabase") { // ② Nom de ta database
      packageName.set("com.example.db") // ③ Package généré
    }
  }
}

dependencies {
  // ④ Driver Android
  implementation("app.cash.sqldelight:android-driver:2.0.2")
  // Extensions coroutines/Flow (optionnel mais recommandé)
  implementation("app.cash.sqldelight:coroutines-extensions:2.0.2")
}
①

Appliquer le plugin dans ce module pour activer la génération de code.

②

AppDatabase est le nom de la classe générée. SQLDelight créera AppDatabase.kt avec toutes tes queries.

③

packageName : le package Java/Kotlin où seront placés les fichiers générés.

④

android-driver encapsule la SQLite native d'Android. Sur iOS tu utiliseras native-driver.

3

Créer ton premier fichier .sq

Crée le dossier src/main/sqldelight/com/example/db/ et ton premier fichier.

Todo.sq 
-- 1. Définir la table
CREATE TABLE Todo (
  id        INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
  title     TEXT    NOT NULL,
  isDone    INTEGER NOT NULL DEFAULT 0
);

-- 2. Requête nommée : récupère tout
selectAll:
SELECT * FROM Todo;

-- 3. Insertion avec paramètres nommés
insertTodo:
INSERT INTO Todo(title, isDone)
VALUES (?, 0);

-- 4. Mise à jour ciblée par id
markDone:
UPDATE Todo SET isDone = 1
WHERE id = ?;

-- 5. Suppression
deleteTodo:
DELETE FROM Todo WHERE id = ?;
2

Le nom selectAll: (avec deux-points) indique à SQLDelight de générer une fonction selectAll() dans TodoQueries.

3

Le ? est un paramètre positionnel. SQLDelight génère une fonction insertTodo(title: String) — typée automatiquement depuis le schéma.

4

Initialiser la base dans ton code

Crée l'instance AppDatabase une seule fois (singleton via DI ou companion object).

DatabaseHelper.kt 
import app.cash.sqldelight.driver.android.AndroidSqliteDriver
import com.example.db.AppDatabase

fun createDatabase(context: Context): AppDatabase {
  // ① Créer le driver Android
  val driver = AndroidSqliteDriver(
    schema   = AppDatabase.Schema, // ② Schema généré
    context  = context,
    name     = "todos.db"         // ③ Nom du fichier .db
  )
  // ④ Retourner l'instance de la DB
  return AppDatabase(driver)
}
②

AppDatabase.Schema contient la version de ta DB et les méthodes de création/migration. SQLDelight le génère automatiquement depuis tes fichiers .sq.

Requêtes

Utiliser les requêtes générées

SQLDelight génère des fonctions Kotlin idiomatiques pour chaque requête nommée.

Lecture de données

Repository.kt 
val queries = db.todoQueries

// Liste complète
val todos: List<Todo> = queries
  .selectAll()
  .executeAsList()

// Un seul résultat (nullable)
val one: Todo? = queries
  .selectById(id = 1)
  .executeAsOneOrNull()

// Avec Flow (reactive)
val flow: Flow<List<Todo>> = queries
  .selectAll()
  .asFlow()
  .mapToList(Dispatchers.IO)
i

executeAsList() : requête synchrone → liste. asFlow().mapToList() : flux réactif qui se met à jour automatiquement. Utilise le Flow en prod avec un ViewModel.

Écriture de données

Repository.kt 
// Insérer
queries.insertTodo(title = "Faire les courses")

// Mettre à jour
queries.markDone(id = 1)

// Supprimer
queries.deleteTodo(id = 1)

// Transaction (atomique)
db.transaction {
  queries.insertTodo("Tâche A")
  queries.insertTodo("Tâche B")
  // Si une ligne échoue, tout rollback
}

// Dans une coroutine
withContext(Dispatchers.IO) {
  queries.insertTodo("Async insert")
}
i

Les transactions garantissent l'atomicité : soit toutes les opérations réussissent, soit aucune n'est appliquée. Toujours faire les écritures sur Dispatchers.IO.

Requêtes avec mapping custom

Todo.sq 
-- Requête avec JOIN et colonnes ciblées
selectWithUser:
SELECT
  t.id,
  t.title,
  u.username AS ownerName
FROM Todo t
JOIN User u ON t.userId = u.id;

-- Filtrage dynamique
selectByStatus:
SELECT * FROM Todo
WHERE isDone = :isDone;
-- Génère: selectByStatus(isDone: Long)
i

La notation :isDone (avec deux-points) crée un paramètre nommé. SQLDelight génère selectByStatus(isDone: Long). Le type est inféré depuis le schéma.

Types personnalisés (adapters)

Todo.sq + AppDatabase.kt 
-- Dans .sq : stocker une enum comme TEXT
CREATE TABLE Todo (
  id       INTEGER NOT NULL PRIMARY KEY,
  priority TEXT AS Priority NOT NULL
);

// Dans Kotlin : créer l'adapter
val adapter = Todo.Adapter(
  priorityAdapter = EnumColumnAdapter()
)
val db = AppDatabase(driver, adapter)
// priority est maintenant Priority, pas String
i

Avec AS Priority dans le .sq, SQLDelight sait que la colonne TEXT doit être mappée au type Kotlin Priority. Tu fournis l'adapter qui sait (dé)sérialiser.

Application Todo — de bout en bout

Un exemple complet avec Architecture Clean, ViewModel et Flow. Copie-colle et adapte.

-- ============================================
-- Todo.sq — Schéma et requêtes complets
-- ============================================

CREATE TABLE Todo (
  id        INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
  title     TEXT    NOT NULL,
  isDone    INTEGER NOT NULL DEFAULT 0,
  createdAt INTEGER NOT NULL
);

selectAll:
SELECT * FROM Todo ORDER BY createdAt DESC;

selectById:
SELECT * FROM Todo WHERE id = :id;

selectByStatus:
SELECT * FROM Todo WHERE isDone = :isDone;

countAll:
SELECT COUNT(*) FROM Todo;

insertTodo:
INSERT INTO Todo(title, isDone, createdAt)
VALUES (:title, 0, :createdAt);

markDone:
UPDATE Todo SET isDone = 1 WHERE id = :id;

markUndone:
UPDATE Todo SET isDone = 0 WHERE id = :id;

updateTitle:
UPDATE Todo SET title = :title WHERE id = :id;

deleteTodo:
DELETE FROM Todo WHERE id = :id;

deleteAll:
DELETE FROM Todo;
// TodoRepository.kt
class TodoRepository(
  private val queries: TodoQueries
) {
  // Flow réactif — se met à jour automatiquement
  val allTodos: Flow<List<Todo>> = queries
    .selectAll()
    .asFlow()
    .mapToList(Dispatchers.IO)

  suspend fun addTodo(title: String) {
    withContext(Dispatchers.IO) {
      queries.insertTodo(
        title     = title,
        createdAt = System.currentTimeMillis()
      )
    }
  }

  suspend fun toggle(todo: Todo) {
    withContext(Dispatchers.IO) {
      if (todo.isDone == 1L)
        queries.markUndone(todo.id)
      else
        queries.markDone(todo.id)
    }
  }

  suspend fun delete(id: Long) {
    withContext(Dispatchers.IO) {
      queries.deleteTodo(id)
    }
  }
}
// TodoViewModel.kt
class TodoViewModel(
  private val repo: TodoRepository
) : ViewModel() {

  // StateFlow exposé à l'UI — jamais la DB directement
  val uiState: StateFlow<TodoUiState> = repo.allTodos
    .map { todos -> TodoUiState(todos = todos) }
    .stateIn(
      scope            = viewModelScope,
      started          = SharingStarted.WhileSubscribed(5000),
      initialValue     = TodoUiState()
    )

  fun addTodo(title: String) {
    if (title.isBlank()) return
    viewModelScope.launch {
      repo.addTodo(title.trim())
    }
  }

  fun toggle(todo: Todo) {
    viewModelScope.launch { repo.toggle(todo) }
  }

  fun delete(id: Long) {
    viewModelScope.launch { repo.delete(id) }
  }
}

data class TodoUiState(
  val todos: List<Todo> = emptyList()
)
// TodoScreen.kt — Compose UI
@Composable
fun TodoScreen(vm: TodoViewModel = viewModel()) {
  val state by vm.uiState.collectAsStateWithLifecycle()
  var text by remember { mutableStateOf("") }

  Column(modifier = Modifier.fillMaxSize().padding(16.dp)) {

    // Champ de saisie
    Row(modifier = Modifier.fillMaxWidth()) {
      TextField(
        value         = text,
        onValueChange = { text = it },
        modifier      = Modifier.weight(1f)
      )
      Button(onClick = { vm.addTodo(text); text = "" }) {
        Text("Ajouter")
      }
    }

    // Liste des todos
    LazyColumn {
      items(state.todos) { todo ->
        TodoItem(
          todo     = todo,
          onToggle = { vm.toggle(todo) },
          onDelete = { vm.delete(todo.id) }
        )
      }
    }
  }
}
// TodoRepositoryTest.kt
class TodoRepositoryTest {

  private lateinit var db: AppDatabase
  private lateinit var repo: TodoRepository

  @Before
  fun setup() {
    // Driver en mémoire pour les tests — rapide !
    val driver = JdbcSqliteDriver(JdbcSqliteDriver.IN_MEMORY)
    AppDatabase.Schema.create(driver) // Créer le schéma
    db   = AppDatabase(driver)
    repo = TodoRepository(db.todoQueries)
  }

  @Test
  fun `add todo then retrieve it`() = runTest {
    repo.addTodo("Apprendre SQLDelight")

    val todos = db.todoQueries.selectAll().executeAsList()

    assertEquals(1, todos.size)
    assertEquals("Apprendre SQLDelight", todos.first().title)
    assertEquals(0L, todos.first().isDone)
  }

  @Test
  fun `toggle marks as done`() = runTest {
    repo.addTodo("Test")
    val todo = db.todoQueries.selectAll().executeAsList().first()
    repo.toggle(todo)

    val updated = db.todoQueries.selectById(todo.id).executeAsOne()
    assertEquals(1L, updated.isDone)
  }
}

FAQ

Questions fréquentes

Le code généré se trouve dans build/generated/sqldelight/. Tu ne dois jamais modifier ces fichiers — ils sont régénérés à chaque build. Si tu changes ton fichier .sq, relance simplement le build avec ./gradlew generateCommonMainAppDatabaseInterface ou appuie sur "Build" dans Android Studio.
Crée des fichiers 1.sqm, 2.sqm dans le dossier migrations/. Chaque fichier correspond à une version de la DB. Par exemple, 1.sqm contient les ALTER TABLE pour passer de la version 1 à la version 2. SQLDelight applique automatiquement les migrations dans l'ordre lors de l'ouverture de la DB. Tu peux tester la cohérence des migrations avec verifyMigrations = true dans la config.
